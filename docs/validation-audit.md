# Validation audit — 19 October 2026

The reproducible inventory is [input-audit.csv](input-audit.csv), generated by `cd DuongSach-FE && node scripts/generate-input-audit.cjs`. It lists all 295 JSX `input`, `textarea`, and `select` controls, their source locations, HTML constraints, and whether they are read only or disabled. It includes 27 controls whose value or placeholder indicates search. This is an inventory of rendered controls; dynamic `contentEditable` fields are validated separately by `validateManagedContent` and `managedContentData`.

## Rules checked

| Area | Validation and behavior |
| --- | --- |
| Search and filters | Search text is trimmed and normalized to Unicode NFC; case folding is applied for local searches. Blank input restores all results. Text search is limited to 200 characters. The admin top bar opens account, role, or settings results; the partner top bar filters activities. Literal punctuation remains literal. |
| API pagination and IDs | `page` and `limit` accept only whole decimal integers in range; malformed, negative, duplicate, decimal, and over-limit values return 422. Facility coordinates stay in 0–100 and capacities are positive integers. |
| Contacts | Email is trimmed and length limited, with an email format check. Account and profile phone numbers follow Vietnamese mobile numbering; support contact also allows Vietnamese landlines and 1800/1900 hotlines. Names use Unicode letters and appropriate punctuation. |
| News and managed content | Publication dates are real calendar dates in DD/MM/YYYY. Reading time accepts 1–999 minutes, including the existing “5 phút đọc” format. URLs allow HTTP(S), local image paths, or supported raster data images. Article text, image captions, tags, array sizes, partner sites/emails, milestone years, and achievement numbers are bounded. Landing content edited directly on the page is checked before any section is saved. |
| Admin forms | Partner contact email is editable and synchronized with the owning organization. Admin department now persists. Settings, profile, library, venue, map, event, news, and user forms have matching field limits; external Save buttons submit their forms so browser constraints are applied. Invalid server submissions return validation errors rather than being silently coerced. |
| Uploaded files | All image pickers check a supported raster MIME type and size before reading. Document pickers check extension, MIME type, filename, size, and list capacity. Partner booth images/documents use a 2 MB file ceiling to stay below the API's 3 million character data URL limit. The API also checks booth image URLs and document sources. |

## Local Docker run

The validation stack uses the **isolated test database** already hosted by the existing PostgreSQL Docker container on port 5434. It is served by `compose.validation.yaml` on `127.0.0.1:8081` (web) and `127.0.0.1:4001` (API). Run `docker compose -f compose.validation.yaml up -d --build`; inspect with `docker compose -f compose.validation.yaml ps`. The stack does not publish to GitHub or a remote server.

## Account ID storage

`User.id` and `Organization.id` are different UUID columns generated by the database. `User.code` is optional and can be null when an admin creates an account. The account list and edit dialog now show the actual `User.id`; the ID is generated by the database and does not belong in the creation form.
